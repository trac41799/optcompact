# Live DeepSeek Harness run, 2026-10-29

**Verdict:** the plugin loaded in a real harness composition. It decided to compact and the stock backend committed two checkpoint transactions.

## Setup

- Profile: `optcompact-smoke`, created from the shipped `headless` template.
- Plugin: `@optcompact/dsh`, bundled to one ESM file and installed with `dsh plugin`.
- Patch: `compaction-basic` with `auto: false`, credentials and authorization enabled, and one policy row.
- Parameters: `tailRatio: 0.001`, `minShadowTokens: 50`, `qualityFloor: 0.3`, `cooldownTurns: 1`.
- Why the low tail floor: the test session is short. The shipped floor needs about 30k tokens.

## Run

Two turns on one session:

1. Read `README.md` and return its first heading.
2. Return the second heading of `README.md`.

Commands:

```powershell
dsh --profile optcompact-smoke --patch <patch.yml> headless --json "<prompt>"
dsh --profile optcompact-smoke --patch <patch.yml> headless --json --session-id <id> "<prompt>"
```

## Decision evidence

`%TEMP%\optcompact-evidence.jsonl` recorded:

```json
{"turn":1,"action":"skip","reason":"insufficient-units"}
{"turn":1,"action":"compact","cutIndex":3,"shadowTokens":779,"retentionRatio":0.05,"cer":1.73}
{"turn":2,"action":"compact","cutIndex":4,"shadowTokens":11578,"retentionRatio":0.05,"cer":14.2}
{"turn":2,"action":"keep","reason":"cooldown"}
```

The `no-step-boundary` guard exists after a first failing run. That run chose an end seq inside a step. The harness rejected it with `end seq 19 is not a balanced boundary`. The guard now snaps a cut to the next `user/message` boundary.

## Harness evidence

The session log (`session.v4.jsonl.zstd`) contains two complete transactions:

```text
compaction/start   seq 23, turn 1
compaction/summary seq 25   (structured checkpoint text)
user/message       seq 26   (framed checkpoint)
compaction/end     seq 27, turn 1
compaction/start   seq 40, turn 2
compaction/summary seq 42
user/message       seq 43
compaction/end     seq 44, turn 2
```

This proves the full path: `agent/pre-step` → `decide` → `compactRegion` → summarizer call → durable checkpoint.

## Limits

- The profile is headless. Web and Desktop isolate the compaction service per preset.
- The tiny tail floor is a test setting, not a recommendation.
- The run used a live model and cost two short turns.
- The plugin profile remains at `%DSH_HOME%\profiles\optcompact-smoke` for reproduction.

## Reproduce

1. Create the profile: `dsh --profile optcompact-smoke --from-default-profile headless --dump-config`.
2. Bundle the plugin: `node node_modules/esbuild/bin/esbuild packages/dsh/src/index.ts --bundle --platform=node --format=esm --outfile=<dir>/index.js`.
3. Install it: `dsh plugin --profile optcompact-smoke add <dir>`.
4. Boot with the patch above and run two turns.
